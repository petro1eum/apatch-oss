# apatch Vision: Portable Professional Capital

> **apatch превращает профессиональный опыт из неформальной памяти человека в переносимый, исполняемый и доказуемый актив.**

---

## Зачем apatch существует

На вопрос «какую проблему решает apatch?» раньше нужно было несколько страниц. Теперь — одна:

```text
Профессионал строит аватар.
Аватар состоит из наработок.
apatch хранит, проверяет, развивает и доказывает эти наработки.
```

Каждый компонент apatch — ответ на конкретную потребность:

```text
Avatar needs memory        → Event Log (contribution history)
Avatar needs proof         → TrustChain (криптографические доказательства)
Avatar needs methodology   → Specs (исполняемые спецификации)
Avatar needs execution     → apatch runtime (governed mutations)
Avatar needs portability   → MCP (подключение к любым AI-инструментам)
```

---

## Что такое «наработки»

Не код. Не данные. Не модели. А **методология в исполняемой форме:**

- **Спеки** — как ты тестируешь, ревьюишь, архитектуришь
- **Автоматизации** — pipeline'ы, governed phases, проверки
- **Паттерны** — архитектурные решения с доказательствами, что работают
- **Аттестации** — криптографически подписанная история: кто, когда, что прошло

Обычное резюме: «Я хороший архитектор.»
apatch repo: 47 спеков + 12 автоматизаций + 200 аттестаций, которые работают с любым AI и доказуемо приносят результат.

## Avatar Compiler — недостающий слой

Без этого слоя apatch — logging system (фиксирует действия, для диагностики, пассивная).  
С ним — **asset system** (интерпретирует ценность, для экономики, переносимая).

```text
apatch_core
  ├── event_log              (что произошло)
  ├── trustchain_attestations (кто подтвердил)
  ├── spec_graph             (какие методологии)
  ├── dependency_graph       (что от чего зависит)
  └── avatar_compiler  ← NEW (агрегирует → интерпретирует → формирует актив)

avatar_compiler:
  input:
    - event_log
    - attestations
    - dependency_graph
  output:
    - artifacts (portable specs — переносимые наработки)
    - contribution_vector (ADR-002 — кто что вложил)
    - asset_summary (Tracker UI — зеркало роста)
    - marketplace_ready_profile (HC layer — готово к рынку)
```

**Ключевое свойство:** compiler — **read-only по отношению к человеку** (не требует дополнительных действий), но **write-creating по отношению к рынку** (создаёт новый актив из уже существующего поведения).

Это убирает главный барьер «career platforms»: не надо вести профиль, заполнять достижения, думать про карьеру как про продукт. **Поведение уже является портфелем.**

### Пять стадий asset pipeline

```text
Event Log (что произошло)
   ↓
TrustChain Attestation (кто подтвердил)
   ↓
Contribution Graph / ADR-006 (история формирования)
   ↓
Avatar Compiler (агрегация → актив)   ← НОВЫЙ СЛОЙ
   ↓
Tracker / Marketplace / HC (отражение → рынок)
```

### Модель «обнаружения», а не «загрузки»

Платформа **не принимает актив — она его обнаруживает.**

Пользователь не «экспортирует данные на платформу». Он работает, apatch накапливает, Avatar Compiler формирует актив, Tracker показывает его — и в какой-то момент человек осознаёт:

> «У меня уже есть портфель инженерного капитала. Я его не создавал как продукт — он возник автоматически.»

Это снижает ощущение «экспорта данных», убирает регуляторный запах «employment brokerage», превращает рынок в natural extension of usage graph.

Тот же принцип — *обнаружение, а не объявление* — теперь работает и внутри инженерной части. **Реестр реальности** (`apatch reality`) делает наблюдаемые факты (баги, инциденты, фидбэк) источником истины, а покрытие проектом этой реальности (`uncovered` = выводимый долг) **считает машина**, а не объявляет человек. И капитал, и долг проступают из работы, а не из ручных отчётов — это и есть конкретная петля обратной связи, которую vision описывает абстрактно.

### Opt-in economic boundary (критично)

apatch core (event log, specs, attestations) = **safe dev tool**. Человек использует его для работы, не для «карьерной платформы».

HC economic interpretation (PI, GPI, Creator Bonus, marketplace) = **явный opt-in**. Compiler создаёт asset_summary, но **экономическая интерпретация** (что это стоит, кому это показать, на какой рынок выйти) — **отдельная product surface**, не скрытая функция core tool.

Это разведение уже частично решено через ADR-003 (fact/declaration/view) и ADR-004 (identity namespaces), но архитектурно важно:

> Avatar Compiler ∈ apatch (creates asset)  
> Economic interpretation ∈ HC Platform (monetizes asset)  
> Граница между ними — **explicit user consent**

## Два vision — apatch и Human Capital

| | apatch | Human Capital |
|---|--------|---------------|
| **Vision** | Portable professional capital | Economic network around portable professional capital |
| **Одной строкой** | Превращает опыт в переносимый актив | Строит рынок вокруг этого актива |
| **Может без другого?** | ✅ Да — работает как GitHub для методологий + trust + AI execution | ❌ Нет — без apatch нечего измерять, доказывать, переносить |
| **Уровень** | Инфраструктура актива | Экономика актива |

apatch может существовать вообще без HC, PI, GPI и Creator Bonus. Человек может пользоваться apatch всю жизнь просто как:

```text
GitHub для методологий
+ Trust layer (доказательства)
+ AI execution layer (governed mutations)
```

Human Capital появляется когда возникает вопрос: **если профессиональный капитал стал измеримым и переносимым — что можно построить поверх него?**

## Как это связывает компоненты

До этого vision каждый компонент выглядел как отдельная инициатива:

| Компонент | Раньше выглядел как | Теперь — часть одного организма |
|-----------|--------------------|---------------------------------|
| TrustChain | Криптографический аудит | **Proof layer** — доказывает происхождение профессионального капитала |
| Specs | Executable specifications | **Methodology layer** — исполняемая форма наработок |
| Attestations | Audit trail | **Growth evidence** — доказательство роста аватара |
| Ledger | Append-only log | **Memory** — история формирования капитала |
| Governance | Sandbox + enforcement | **Integrity** — гарантия что наработки не подделаны |
| Coverage | Spec requirement tracking | **Completeness** — какие методологии освоены и доказаны |
| MCP | Tool connectivity | **Portability** — наработки работают с любым AI |

## Почему это не очередной DevOps-инструмент

Большинство инженерных платформ стартуют снизу:

```text
Git → CI/CD → DevOps → Observability → ???
```

…а потом пытаются придумать vision.

apatch пошёл наоборот. Постепенно выяснилось, что это:

- **Не** про спецификации (хотя спеки — ключевой механизм)
- **Не** про TrustChain (хотя trust — фундамент)
- **Не** про аттестации (хотя они — доказательная база)
- **Не** про AI (хотя AI — execution layer)

А про **сохранение и перенос накопленного профессионального капитала**.

## Связь с ADR (Human Capital)

Если apatch repo — это аватар, то ADR Human Capital объясняют **экономику** вокруг него:

| ADR | Что объясняет в контексте аватара |
|-----|----------------------------------|
| ADR-003 | Что считать фактом, а что интерпретацией (наработки vs мнения) |
| ADR-004 | Кому принадлежит накопленный капитал (identity = ownership) |
| ADR-006 | Как хранится история формирования капитала (event log) |
| ADR-007 | Что такое аватар как продукт и почему это не продажа работника |
| TrustChain | Доказывает происхождение капитала |
| HC Economy | Строит рынок вокруг этого капитала (PI, GPI, Creator Bonus) |

## Формулировки для разных аудиторий

**Для инженера:**
> apatch — governed mutation runtime с TrustChain и executable specs, который превращает профессиональный опыт в переносимый, версионированный, доказуемый актив.

**Для руководителя:**
> apatch фиксирует, как ваши инженеры работают — не что они пишут, а какие методологии, паттерны и автоматизации они создают. Эти наработки принадлежат человеку и переносятся между компаниями. Ваш вклад (инфраструктура, данные, модели) отделён и компенсируется при трансфере.

**Для инвестора:**
> apatch создаёт новый тип цифрового актива — portable professional capital. Пользователь не строит профиль — актив возникает автоматически из ежедневной работы. Human Capital строит экономическую сеть вокруг этого актива.

**Одной строкой:**
> **apatch = GitHub for professional methodology, with trust.**

**Класс системы:**
> **Автоматическая капитализация профессионального поведения без изменения поведения пользователя.**
