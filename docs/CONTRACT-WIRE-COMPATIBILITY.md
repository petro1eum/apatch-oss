# Совместимость native CDD-документов v1

Профиль `cowork-exact-v1` описывает совместное использование уже существующих
форматов. Это имя профиля проверки, а не новое поле, универсальная схема подписи
или версия бизнес-договора. Проверка формата не создаёт согласия, допуска или
свидетельства исполнения.

| Документ | Владелец | Поддерживаемая версия и роль |
| --- | --- | --- |
| Frozen verification contract | APatch Core | `apatch.sdd.verification-contract.v1`: фиксирует технического проверяющего |
| Task envelope | APatch Core | `apatch.sdd.task-envelope.v1`: scope, ссылки на договор и бюджет |
| Снимок пользовательского договора | Platform | `trustchain.cowork.initial-contract-snapshot.v1`: неизменяемая композиция условий, native-документов и сторон |
| Exact handoff | Platform | `trustchain.apatch-studio.exact-contract-bundle.v1` / `…handoff.v1`: существующая передача в Studio |
| Чтение и исполнение | Studio | Проверяет native-профиль Core и отдельно существующие подписи/полномочия handoff |
| Браузерный адаптер | Cowork UI | Проверяет форму и поддерживаемые значения; не удостоверяет content seal, подпись, стороны или исполнение |

## Значения и границы

- Все четыре `budgets.files/insertions/deletions/seconds` обязательны. Это числа
  целого типа от 0 до 9007199254740991. Строки, boolean, null, дробные числа,
  целочисленные float вроде `1.0`, отрицательные и небезопасные целые серверные
  читатели отвергают. Новые значения не приводятся через `int(value or 0)`.
  Семантика нулей и накопления расхода остаётся определённой CDD-G05.
- Схемы должны иметь точные версии выше. Неизвестная версия отвергается;
  создание документа не понижает v2 до v1 автоматически.
- Envelope ссылается на точные contract/baseline hashes, requirement вида
  `SPEC-UPPERCASE-ID#R1` и существующие checks. Ключ `R1` совпадает с requirement;
  все envelopes снимка относятся к одной SPEC. Argv совпадает с выбранными
  проверками и их content pins; списки scope уникальны и каноничны.
- Для exact-профиля обязательны полное coverage без waivers, authority,
  pre-implementation freeze, явный `judge_environment={cwd,env}`, тип boolean
  у material и точные asset mappings. Формат известных вложенных объектов
  `budgets`, `judge_environment` и judge asset закрыт. Профили falsification
  `reversible_seed` и `reversible_builtin_mutant` поддерживаются с существующими
  значениями `expected=red`, target path/hash.
- Неизвестные поля верхнего уровня native contract/envelope сохраняются как
  непрозрачные данные, входят в content hash и не предоставляют полномочий.
  Неподдерживаемую семантику нельзя включить таким полем; для её исполнения
  требуется явно поддержанная версия/профиль. Неизвестные budget-поля отвергаются.
- Общий native v1 допускает другие локальные сценарии. Это не утверждение, что
  любой произвольный v1 без обязательного `judge_environment` пригоден для exact
  handoff. Читатель exact-профиля выдаёт конкретный отказ до исполнения, а не
  дописывает поля в старый документ.

## Байты и совместимость истории

Content seal остаётся прежним: `sha256:` + SHA-256 UTF-8 от Python-compatible JSON
без `document_hash`, с `sort_keys=True`, `ensure_ascii=False`, `allow_nan=False`
и разделителями `,` / `:`. Это существующее правило, не переход на JCS.
Порядок ключей входного объекта не меняет hash; Unicode не нормализуется:
разные последовательности Unicode остаются разными байтами.

Чтение sealed envelope не изменяет его значения, списки или content hash.
Если нормализация изменила бы документ, требуется явный новый документ;
автоматического исправления подписанного содержимого нет. Изменённые байты со
старым content seal отвергаются. Подписи, доверенные ключи, согласия, idempotency
и допуск исполнения проверяются прежними владельцами отдельно.

JavaScript не различает распарсенные JSON `1` и `1.0`. Поэтому UI-проверка
`Number.isSafeInteger` не заменяет строгий серверный тип и проверку content seal.
В корпусе такие случаи, а также подменённый seal/command pin, имеют отдельное
ожидание для advisory browser shape. Приёмка native-документа остаётся серверной.

## Общий тест совместимости

Единый корпус: `tests/fixtures/sdd_wire_v1.json` в APatch. Он содержит 33 общих
примера, положительные выходы настоящего Core producer, отрицательные типы,
версии/ссылки, закрытые вложенные поля, Unicode и golden canonical bytes/hash.
Это тестовые content seals, не подписи, согласия или реальные результаты judge.

Его читают независимый Platform boundary validator, native validator Core,
точный Studio reader и TS-адаптер Cowork. Проверки заново создают поддерживаемые
выходы producer и передают их потребителям без промежуточного редактирования;
проверяют неизменность входа и существующие хеши. Команды и пределы фактической
проверки сохранены в `TrustChain_Agent/docs/DEVELOPMENT-VERIFICATION.md`, CDD-G07.
