# apatch reality — наблюдаемая реальность как источник истины

> Append-only реестр наблюдаемых фактов, которые проект обязан закрыть; требования спеки их
> **дискорджат** (закрывают). Покрытие считается не от полноты прозы, а от того, **какая доля
> реальности закрыта зелёным гейтом**. Реализация — `apatch/reality.py`; CLI — `apatch reality *`; MCP — `apatch_reality(action=…)`.
> Универсально (RFP-005): `source`/`kind` — свободные строки, без завязки на домен.
> Смежное: [probe.md](./probe.md) (качество гейта), [conformance.md](./conformance.md) (держится ли контракт).

---

## Инверсия источника истины

Обычно спека — главная, а реальность сверяют с ней. Здесь наоборот: **реальность стоит над
спекой**, а спека ей подотчётна.

```
баг / инцидент / тикет / фидбэк / трейс / находка   →   REC-…   (наблюдаемый факт, append-only)
требование заявляет, что закрывает его              →   (discharges: REC-…)
гейт зелёный И аттестован                           →   covered

  uncovered = наблюдаемое ∧ не закрыто зелёным гейтом   ←   ДОЛГ по построению
```

**Почему это лучший якорь против дрейфа:** проза может разойтись с правдой и никто не заметит.
Реальность — *отдельный* append-only леждер; долг спеки перед ней считает машина. Новая запись —
**недискорженный долг by construction**, пока какое-то требование её не заявит. `uncovered` —
чистая деривация, а не ручной ярлык, который кто-то забыл проставить.

Это **не замена** спеки: внутренние инварианты живут в ней по-прежнему. К реальности привязано
только reality-coupled подмножество — то, что родилось из наблюдения.

## Запись (`REC-…`)

| Поле | Смысл |
|------|-------|
| `id` | Стабильный `REC-<sha12>` (по умолчанию — хэш `source\|summary`; идемпотентно) |
| `summary` | Что наблюдали (баг/инцидент/фидбэк/находка) |
| `source` | Откуда пришло — трекер / телеметрия / поддержка / аудит (свободная строка) |
| `kind` | `bug` \| `incident` \| `feedback` \| `finding` \| `observation` \| … (свободная) |
| `status` | `open` \| `closed_wontfix` (wontfix — явное датированное снятие обязательства) |
| `observed_at` | UTC-метка |

Леждер — `.apatch/reality.jsonl` (append-only, идемпотентно по `id`, capped 5000).

## CLI

```bash
# 1) наблюдаемый факт попадает в леждер
apatch reality add --summary "checkout 500 на купоне" --source linear --kind bug
#   ✓ reality REC-574d7191c6bc: checkout 500 на купоне

# 2) покрытие реальности: что закрыто зелёным гейтом, а что — долг
apatch reality status            # (--json для CI: exit 0 если долга нет, иначе 1)
#   reality coverage: 0 covered · 0 pending · 1 uncovered (of 1)
#     uncovered REC-574d…: checkout 500 на купоне  (linear)
```

> **MCP vs CLI.** Через MCP `apatch_reality(action='status')` возвращает операционный
> `ok: true` (запрос удался), а сигнал «чисто ли покрытие» — в отдельном поле `clean`
> (`true` = долга нет) рядом с `uncovered`; «есть долг» **не** трактуется как сбой тула
> (это [REC-7855], которую мы и закрыли). CLI `apatch reality status` использует тот же
> сигнал как exit-code (`0` если чисто, иначе `1`).

Требование в спеке заявляет, что закрывает запись, — строкой `discharges`:

```markdown
## R1 купон не должен ронять checkout (verify: pytest tests/test_coupon.py) (discharges: REC-574d7191c6bc)
```

Тогда статус записи проходит траекторию:

```
uncovered            нет требования, которое её заявляет        ← долг
  → pending          требование заявило, но гейт ещё не аттестован
  → covered          discharges-требование зелёное И аттестовано
```

`status=closed_wontfix` убирает запись из обязательства (датированное «не чиним»).

## Под капотом (чистое ядро)

```python
from apatch.reality import reality_coverage  # PURE
cov = reality_coverage(records, discharge_map, attested)
# covered  — запись дискорджена ХОТЯ БЫ ОДНИМ аттестованным требованием
# pending  — дискорджена, но ни одно заявляющее требование пока не аттестовано
# uncovered— ни одно требование не дискорджит (недискорженный долг реальности)
# ok       — True только когда нет ни uncovered, ни pending
```

`reality_coverage` — чистая функция: парсинг `discharges` из спек и чтение аттестаций (из ledger)
делает CLI/`reality status`, а классификация — здесь. Никакого ввода-вывода, легко тестировать.

## Чего reality НЕ делает

- Не пишет записи за тебя — наблюдения приходят из мира (ты/CI/телеметрия зовут `reality add`).
- Не заменяет спеку — добавляет ей **подотчётность реальности**, не отменяя внутренние инварианты.
- Не решает приоритет — `uncovered` показывает долг; *что* закрывать первым решаешь ты.
